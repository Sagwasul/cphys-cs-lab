# 用户自定义内容

这个目录用于**把你自己写的课程贡献到仓库**（可选）。

日常使用不需要碰这里——直接在网站的「我的内容」（`#/mine`）页面创建、编辑、保存即可，
数据存在你自己的浏览器里（IndexedDB），并且可以导出成 JSON 备份。

只有当你希望这份内容成为**站点内置课程**（所有访问者都能看到）时，才走下面的 PR 流程。

---

## 两种方式

### 方式 A：提交 Markdown（最省事，适合纯知识笔记）

1. 在 `user-content/` 下新建一个 `.md` 文件，按 `template.md` 的结构写。
2. 提 PR。

维护者会把它转换成 `content/user/*.js`（内置课程格式），然后在网站上出现。

**优点**：写起来最舒服，专注内容。
**限制**：这种方式写的内容没有交互式 demo 与自动测试（因为 Markdown 里没法带可执行代码）。

### 方式 B：提交内置课程格式（功能完整）

1. 在网站上用「我的内容」写好课程，点**导出**得到 JSON。
2. 复制 `content/user/example-lesson.js` 作为模板，把 JSON 里的字段填进去。
3. 保存到 `content/user/<你的课程名>.js`。
4. 本地验证：

   ```bash
   npm run build      # 契约校验 + 密钥扫描
   npm test           # 大纲完整性会检查你这节课
   ```

5. 提 PR。

**优点**：能带交互式 demo（如果用了已注册的 `demo.kind`）、自动测试、AI 引导问题。
**限制**：必须满足课程的 8 段式契约（见下）。

---

## 内置课程格式的硬性要求

构建脚本与测试会逐条检查，缺一项就会失败：

1. **文件第一行**必须是元数据（前面不能有任何内容）：

   ```js
   //__CPL_META__ {"id":"user-my-topic","module":7,"week":99,"title":"我的主题","subtitle":"一句话","tags":["自定义"]}
   ```

   - `id` 建议以 `user-` 开头，避免与内置课程冲突
   - `week` 用 99 表示"不占用正式周次"，会排在课表末尾

2. 必须是**经典脚本**（不是 ES 模块）。禁止出现：
   - `import ... from`
   - `export`
   - `eval(`
   - `new Function(`
   - `document.write`

   （原因：课程文件由 `<script src>` 按需加载，且内容应当是**数据**而不是可执行逻辑。
   这样审阅 PR 时只需要看内容对不对，不需要审代码。）

3. 必须调用 `CPL.registerLesson({...})`，并包含这些字段：

   | 字段 | 要求 |
   | --- | --- |
   | `objectives` | ≥1 条，用可检验的动词（能解释、能预测、能推导） |
   | `concepts` 或 `sections` | ≥1 条，正文用 Markdown |
   | `demo` 或 `sections` | 若要交互 demo，`demo.kind` 必须是已注册的（见 `pieces/82-demos.js`、`pieces/83-demos-cs.js`） |
   | `exercise` 或 `sections` | 代码练习（可选） |
   | `tests` | ≥1 条自动测试 |
   | `aiPrompts` | ≥1 条，**每一条必须以 `？` 结尾** |
   | `anki` | ≥1 张卡片，`{front, back}` |
   | `reading` | ≥1 条延伸阅读 |
   | `checklist` | ≥1 条自检项 |

   如果你的内容是纯笔记，用 `sections: [{title, body}, ...]` 就够了，
   渲染器会自动把它当作"核心概念"展示。

4. 单个文件 ≤ 200 KB。

## Markdown 支持范围

课程正文支持：

- 标题 `#`..`######`、**粗体**、*斜体*、`行内代码`、~~删除线~~、==高亮==
- 围栏代码块（**建议标注语言**，会获得语法高亮）：```` ```python ````、```` ```fortran ````、```` ```c ````、```` ```bash ````
- 表格、有序/无序列表、任务列表 `- [ ]` / `- [x]`
- 引用 `>`，以及**提示框**：

  ```
  > [!PHYSICS] 物理直觉
  > 这里写物理意义。

  > [!NUMERIC] 数值陷阱
  > 这里写数值上的坑。
  ```

  可用类型：`NOTE` `TIP` `IMPORTANT` `WARNING` `CAUTION` `PHYSICS` `NUMERIC` `DEBUG` `EXAM`

- 公式：行内 `$E = mc^2$`，块级 `$$\int_0^1 x^2 dx = \frac{1}{3}$$`
- 链接与图片（`http(s)` 外链会自动加 `rel="noopener noreferrer"`）
- **原始 HTML 不会被渲染**（会被转义显示）——这是有意的安全设计

## 审阅标准（维护者看什么）

1. **事实正确性**：公式、数值、API 用法是否正确？引用是否指向真实文档？
2. **是否有具体锚点**：每个概念都挂在一个代码片段、一个实测数字、或一个物理场景上？
   "什么是大 O"这种空洞的条目会被要求改成"N 从 10⁴ 到 10⁶，O(N²) 耗时放大多少倍"。
3. **是否遵守三条判断准则**：概念性知识要能"自己推回来"，工具性细节要能"30 秒查到"。
4. **不涉及私人事务**：不写面试、简历、求职、薪资相关内容。这一条是硬要求。
5. **自动测试是否真的在测东西**：`assert` 里必须真有断言；计时断言必须是**比值**而不是绝对耗时（否则换台机器就失败）。

提交 PR 即表示你同意你的内容以本仓库的 MIT 许可证发布。
